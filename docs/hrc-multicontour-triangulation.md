# HRC multi-contour polygon triangulation

The class-4 geometry corpus uses vertex index `0xFFFFFFFF` inside a polygon corner stream as a contour separator. Manual Blender geometry supplied by the project owner gives an independent topology-count check for how those records should be tessellated.

## Proposed production rule

For one source polygon containing multiple contours:

1. preserve each contour as an ordered loop of source corner records;
2. calculate a stable polygon plane from the source geometry (Newell normal is sufficient for the validated cases);
3. project all contours to the dominant 2D plane;
4. choose the contour with the largest absolute projected area as the exterior shell;
5. treat the other contours as holes;
6. perform constrained triangulation of the resulting polygon;
7. map triangle vertices back to the original source corners so source UVs/normals remain available.

Only multi-contour polygons require this tessellation. Ordinary class-4 polygons should remain untouched unless the target format itself requires triangulation.

## Manual walker parity

The archived high-resolution walker source and the manually converted `bz2walker.blend` provide exact count checks.

### `extru12`

Source HRC:

- 344 vertices;
- 260 polygons total;
- 2 multi-contour polygons;
- each multi-contour polygon contains contours of 6 and 80 vertices.

Constrained triangulation produces **86 triangles per multi-contour polygon**.

Therefore:

```text
258 ordinary source polygons
+ 86 triangles
+ 86 triangles
= 430 output polygons
```

The manual Blender mesh is exactly **344 vertices / 430 polygons**.

### `bool4`

Source HRC:

- 524 vertices;
- 353 polygons total;
- 2 multi-contour polygons;
- first multi-contour polygon: 77-vertex and 81-vertex contours;
- second multi-contour polygon: 4-vertex and 80-vertex contours.

Constrained triangulation produces **158** and **84** triangles respectively.

Therefore:

```text
351 ordinary source polygons
+ 158 triangles
+ 84 triangles
= 593 output polygons
```

The manual Blender mesh is exactly **524 vertices / 593 polygons**.

The same behavior explains the systematic count differences across the other affected walker parts: meshes without contour separators match the HRC polygon count directly; meshes with separators gain only the faces generated by tessellating those multi-contour source polygons.

## Corpus scale

With embedded ZIP HRCs included, the supplied art corpus contains:

- 708 contour-separator records;
- 703 multi-contour polygons;
- 376 class-4 records containing at least one separator;
- up to 3 contours in one source polygon.

These are valid recoverable source polygons, not corrupt geometry.

## Validation boundary

The manual Blender comparison proves polygon-count parity for representative high-resolution walker meshes. A later geometry-level comparison should also check triangle connectivity/winding and output vertex positions. The original HRC corner stream remains authoritative even when a manually converted Blender derivative uses a different triangulation ordering.
